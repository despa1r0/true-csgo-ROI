# trueROI — каталог и сравнение CS2-предметов

Веб-приложение сравнивает цены CS2-предметов и рассчитывает реальную прибыль после комиссий. Текущий этап — React-каталог с живыми данными CSFloat, CSGO Market и White.Market, модальной аналитикой и отдельным калькулятором сделок.

## Что уже работает

1. PostgreSQL в Docker с постоянным volume.
2. Автоматический импорт актуальных скинов из ByMykel/CSGO-API.
3. React + TypeScript + Vite frontend в `frontend-react` с RU/EN локализацией.
4. Поиск по частичному названию с превью.
5. Фильтры по оружию, редкости и коллекции.
6. Карточки wear-качеств с минимальными ценами доступных площадок.
7. Модальный список лотов и подробная аналитика с возвратом в каталог.
8. Вкладки реальной истории, активных лотов, быстрой продажи и сравнения площадок.
9. Графики реальных продаж за 24 часа, 7 дней, 14 дней и всю доступную историю без синтетических данных.
10. White.Market явно помечен как площадка без публичной истории продаж.
11. Текущие buy orders, цена быстрой продажи и beta-оценка ликвидности.
12. Фильтры листингов по float, Normal / StatTrak™ / Souvenir, цене, наличию наклеек и charm.
13. Самостоятельные наклейки и charms ищутся в общем каталоге; фильтры attachments внутри лотов проверяют только наличие, без выбора конкретного имени/ID.
14. Динамические capabilities управляют поддержкой лотов, истории, quick sell, float, наклеек, charm и `best_deal`.
15. Отдельный `/calculator` с ручными ценами, выбором скина, swap площадок и режимами Raw, Smart, Enhanced, Quick flip и Custom.
16. Пользовательские чекбоксы учёта комиссий при неизменяемых server-owned ставках.
17. Публичный индекс цен, лоты, стакан и история CSGO Market.
18. Лоты и quick sell White.Market через отдельный адаптер.
19. Общий PostgreSQL-кэш рыночных данных.
20. Сравнение цен и направлений сделки с учётом комиссий.
21. Защищённый лимит приватного API CSGO Market: не более 4 запросов/с.
22. Multi-stage Docker-сборка React-приложения и FastAPI в одном production-образе.
23. Отдельные тесты границы поддержки наклеек/charm в `tests/test_listing_attachment_capabilities.py`.

## Модель данных

`skins` хранит базовый скин, например `AK-47 | Redline`. `skin_variants` хранит реальные рыночные варианты, например `StatTrak™ AK-47 | Redline (Field-Tested)`. Связь выполняется по `skin_id` источника.

Рыночное имя, float-диапазон, paint index, редкость, изображение и исходный JSON сохраняются в БД. `skin_collections` связывает скины с коллекциями. `marketplace_listings` хранит индекс цен, `marketplace_syncs` — время общей синхронизации, `marketplace_variant_details` — кэш подробных листингов и метрик.

## Следующие этапы

1. При необходимости накапливать собственную историю снимков цен и продаж длиннее доступной истории источников.
2. Калибровать ликвидность на более длинном временном окне.
3. Добавить поиск конкретных наклеек и charm по нормализованным имени/ID.
4. Подключать новые площадки через реестр capabilities и отдельные адаптеры.
5. Расширять автоматический поиск возможностей между площадками.

## Формула прибыли

```text
effective_buy = buy_price + buy_fees
effective_payout = sell_price - sell_fees
profit = effective_payout - effective_buy
roi = profit / effective_buy * 100
```

Деньги передаются и хранятся в центах, а не в `float`. Profit Engine не выполняет HTTP-запросы и работает только с нормализованными ценами и комиссиями.
