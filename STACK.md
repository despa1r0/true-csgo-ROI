# PROJECT.md — Skin Market Tracker

## Идея

Skin Market Tracker — приложение для централизованного сравнения цен на CS2-скины между различными торговыми площадками.

Основная задача проекта — показывать не только разницу между ценами на маркетплейсах, но и **реальный потенциальный profit с учётом комиссий, ликвидности и способа продажи**.

Проект не должен быть простой копией PriceEmpire или CSMarketCap.

Главная идея:

> Найти не просто разницу цен, а определить, можно ли эту разницу реально превратить в прибыль.

---

## Основные источники данных

На первом этапе планируется работа с:

* CSFloat;
* CS.MONEY;
* Skins.com;
* PriceEmpire как агрегатором рыночных данных.

Каждый внешний API должен подключаться через отдельный adapter.

Внутренняя логика приложения не должна зависеть от структуры конкретного API.

```text
External APIs
     │
     ▼
Adapters
     │
     ▼
Normalized models
     │
     ▼
Application services
```

## MVP

### 1. Поиск скинов

Пользователь вводит название:

`Redline`

Приложение должно найти семейство:

`AK-47 | Redline`

и показать доступные варианты износа:

* Factory New;
* Minimal Wear;
* Field-Tested;
* Well-Worn;
* Battle-Scarred.

Варианты группируются по типу:

* Normal;
* StatTrak;
* Souvenir.

По умолчанию используется `Normal`.

Для каждого варианта показываются:

* минимальная цена;
* маркетплейс с минимальной ценой;
* ликвидность;
* актуальность данных.

---

## 2. Marketplace comparison

После выбора конкретного скина пользователь видит цены на доступных площадках.

Пример:

```text
AK-47 | Redline (Field-Tested)

CSFloat        $18.40
Skins.com      $18.75
CS.MONEY       $19.10
```

Цена маркетплейса должна содержать ссылку на страницу предмета на соответствующей площадке.

---

## 3. Profit Engine

Profit Engine — центральный компонент приложения.

Он должен рассчитывать не только raw spread:

```text
sell_price - buy_price
```

но и realistic profit.

Учитываются:

* цена покупки;
* комиссия пополнения;
* комиссия способа оплаты;
* комиссия продажи;
* комиссия вывода;
* возможная конвертация валют;
* выбранная стратегия продажи.

Результат:

```text
Buy price:            $18.40
Buy fees:              $0.18
Effective buy:        $18.58

Expected sell:        $19.70
Selling fees:         -$0.79
Effective payout:     $18.91

Estimated profit:     +$0.33
ROI:                  +1.78%
```

Profit Engine не должен самостоятельно обращаться к внешним API.

Он получает уже нормализованные данные и выполняет только бизнес-логику и вычисления.

---

## 4. Exit Strategy

Для расчёта предполагаемой цены продажи пользователь может выбирать стратегию.

### Lowest Listing

Использовать текущий самый дешёвый listing.

Это потенциальная цена продажи, но она не гарантирует продажу.

### Quick Sell

Если доступны buy orders, использовать лучший существующий buy order.

Это должно показывать приблизительную сумму, которую можно получить при максимально быстрой продаже.

### Market Price

Использовать более реалистичную оценку рыночной стоимости.

На первом этапе можно использовать:

* median recent sales;
* данные PriceEmpire;
* другой простой статистический показатель.

Позже алгоритм можно улучшать.

---

## 5. Liquidity

Приложение должно учитывать ликвидность предмета.

Возможные показатели:

* количество продаж за 24 часа;
* количество продаж за 7 дней;
* количество активных listings;
* количество buy orders;
* spread между sell listings и buy orders.

Пользователь должен понимать разницу между:

```text
Profit: +8%
Liquidity: HIGH
```

и:

```text
Profit: +80%
Liquidity: VERY LOW
```

Второй вариант может быть практически невозможно реализовать.

---

## 6. Portfolio

Portfolio разрабатывается после поиска, сравнения цен и Profit Engine.

Первоначально — manual mode.

Пользователь вручную добавляет:

* предмет;
* marketplace;
* цену покупки;
* комиссии;
* дату.

После продажи:

* marketplace продажи;
* цену продажи;
* комиссии;
* дату.

Приложение рассчитывает:

* realized P&L;
* unrealized P&L;
* ROI;
* историю сделок.

Позже можно добавить automatic mode через API торговых площадок, если они предоставляют доступ к истории пользовательских транзакций.
