# Frontend trueROI

Актуальный frontend расположен в `frontend-react` и реализован на React, TypeScript и Vite. Старый каталог `frontend` не участвует в production-сборке: Docker собирает `frontend-react/dist`, после чего FastAPI раздаёт результат с того же origin, что и `/api/*`.

## Стек

- React 19 и TypeScript;
- Vite 7;
- React Router;
- TanStack Query для серверного состояния;
- i18next/react-i18next для RU/EN;
- Radix Dialog для модальных окон;
- ECharts для истории продаж;
- Motion для коротких интерфейсных анимаций;
- Vitest и Testing Library для frontend-тестов.

## Маршруты

| Маршрут | Назначение |
| --- | --- |
| `/` | каталог всех типов предметов, поиск, фильтры, сравнение цен и лоты |
| `/calculator` | самостоятельный калькулятор профита |

Модальное окно лотов и аналитики закрывается с возвратом в каталог. Внутри доступны вкладки истории продаж, активных лотов, быстрой продажи и сравнения площадок. `Active listings` позволяет выбрать отдельную площадку или `All marketplaces`. Таблица активных лотов и карточки показывают изображения наклеек и charms; hover показывает справочную цену attachment только тогда, когда её передал провайдер. Во вкладке сравнения есть два визуальных превью предметов со всеми доступными attachments; прибыль подсвечивается зелёным, убыток красным.

## Рыночные данные и capabilities

Список площадок и их возможности загружаются из `GET /api/marketplaces`. Frontend использует флаги `can_buy`, `can_sell`, `supports_quick_sell`, `supports_listings`, `supports_sales_history`, `supports_float`, `supports_stickers`, `supports_charms` и `supports_best_deal_sort`. Благодаря этому новую площадку можно подключать через серверный реестр и адаптер без отдельного жёстко заданного интерфейса.

ROI-каталог принимает только пригодные для торговли source entries. Записи без явного `market_hash_name`, account-bound и preview/unreleased определения, а также неподдерживаемые collectibles исключаются при импорте. Новые типы предметов запрашиваются у площадок по точному `market_hash_name`, а не через `paint_index`.

История продаж имеет периоды 24 часа, 7 дней, 14 дней и «Доступная». Каждая точка ECharts соответствует записи, полученной от площадки; синтетические продажи, интерполяция и продолжение ряда отсутствуют. CSFloat и CSGO Market возвращают доступную историю источника. Публичная история CSGO Market не содержит float. White.Market не предоставляет public sales history, поэтому для него интерфейс показывает недоступность истории, а не пустой или сгенерированный график.

## Калькулятор профита

На `/calculator` можно вручную задать фактические цены покупки и продажи либо выбрать скин и использовать текущую рыночную цену как ориентир. Ручное значение не заменяется рыночной ценой автоматически. После расчёта интерфейс показывает прибыль по фактической покупке, отдельный результат по рыночной цене, дополнительную прибыль и разницу ROI. Доступны выбор площадок, swap направления, способы пополнения/вывода, обычная или быстрая продажа и режимы Raw, Smart, Enhanced, Quick flip и Custom.

Чекбоксы `use_deposit_fee`, `use_sell_fee` и `use_withdraw_fee` определяют, какие комиссии учитывать. Пользователь управляет только включением комиссии; проценты и фиксированные суммы остаются server-owned и приходят из `/api/marketplaces`. Итоговый расчёт выполняет `POST /api/calculate`, а не браузер.

`Smart` сравнивает lowest ask покупки с lowest ask будущего листинга на продаже и применяет серверные комиссии. Это ask-to-ask ориентир, а не обещание мгновенного исполнения. `Quick flip` вместо sell ask использует лучший доступный bid. Liquidity является только диагностической метрикой detail-экрана: она не передаётся в Profit Engine и не корректирует profit или ROI.

## Наклейки и charm: текущая граница

Общий каталог ищет наклейки и charms как самостоятельные рыночные предметы по названию. Отдельно в браузере лотов доступны фильтры наличия `has_stickers` и `has_charm`; они пока не фильтруют attachments по конкретному названию либо ID.

- CSFloat: оба фильтра наличия;
- White.Market: оба фильтра наличия передаются в GraphQL;
- CSGO Market: фильтр наличия наклеек; charm-данные площадкой не предоставляются, поэтому charm-фильтр возвращает пустой результат;
- доступность контролов в UI определяется capabilities площадки.

Эта граница зафиксирована отдельным набором `tests/test_listing_attachment_capabilities.py`: тесты проверяют поведение трёх адаптеров и OpenAPI-контракт, в котором есть только boolean-параметры наличия и нет параметров поиска attachment по имени/ID. Frontend-тест `src/shared/api/endpoints.test.ts` проверяет, что API-клиент отправляет оба boolean-фильтра и не добавляет выдуманные параметры поиска по имени.

## Локальная разработка

Требуется Node.js 20.19 или новее. Из каталога `frontend-react`:

```bash
npm install
npm run dev
npm test
npm run build
```

`npm run dev` запускает Vite и проксирует `/api` на локальный FastAPI согласно `vite.config.ts`. `npm test` запускает Vitest один раз, а `npm run build` сначала проверяет TypeScript, затем создаёт production bundle в `dist`.

## Docker

Корневой Dockerfile использует multi-stage build:

1. стадия `node:22-alpine` выполняет `npm ci` и `npm run build`;
2. стадия `python:3.13-slim` устанавливает backend-зависимости;
3. готовый `/frontend/dist` копируется в `/app/frontend` и раздаётся FastAPI.

Так production-образ не требует Node.js во время выполнения и обслуживает UI и API на одном адресе.
